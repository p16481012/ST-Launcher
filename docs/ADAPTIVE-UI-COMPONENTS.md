# 3단계 공통 UI 구성요소

## 변경 범위

- `AdaptiveInfoRow`: 카드 내부 폭이 360dp 미만이거나 글꼴 배율이 130% 이상이면 이름과 값을 세로로 배치합니다. 값은 생략하지 않고 줄바꿈합니다.
- `chooseLauncherNavigation`: 현재 앱 창 폭 600dp를 기준으로 하단 탐색/측면 탐색을 선택합니다. 물리 화면 크기가 아니라 분할 화면을 포함한 현재 창 폭을 전달해야 합니다.
- `LauncherNavigationRail`: 짧은 가로 창에서도 모든 메뉴에 접근할 수 있도록 세로 스크롤을 제공합니다.
- `serverStatusIndicatorColor`: 준비·진행·경고·오류·꺼짐 상태에 의미색을 부여하고 실제 카드 배경에서 대비가 더 높은 색조를 선택합니다. 상태 설명 텍스트를 함께 표시해야 하며 색만으로 상태를 전달하지 않습니다.
- `SillyTavernLauncherTheme`: 시스템 테마는 기기의 밝기 모드를 따릅니다. 강조색은 배경화면과 무관하게 설정에서 선택하며 기존 자두·아보카도·바나나·블루베리 테마도 유지합니다.
- 메인 화면에 위 구성요소를 연결했습니다. 넓은 창의 본문은 최대 840dp로 제한하고, 관리·진단·설정의 하위 이동은 탭으로 구분합니다. 초기화는 접힌 위험 영역으로 분리하고, 꺼진 서버에는 재시작 바로가기를 표시하지 않습니다.
- 펼친 작업 창은 네이티브 모달 Dialog로 외부 터치를 차단합니다. 접으면 단계·전체 경과 시간·측정된 처리량을 표시하며, 수동 16ms 회전 루프는 네이티브 진행 표시로 대체했습니다.
- 새 탭/위험 영역/진행 패널/브랜치 경고 문구는 `strings_stage3.xml`로 분리했습니다. 기존 화면 전체 문구를 일괄 이동한 것은 아닙니다.

## 추가한 테스트

- `AdaptiveLayoutPolicyTest`: 창 폭 320/360/411/599/600/720/840/1280dp, 큰 글씨 130%/200%, 잘못된 측정값의 안전한 기본 동작을 검사합니다.
- `ThemePolicyTest`: 앱 글자 배율, 밝고 어두운 화면에서 강조색 대비 4.5:1, 서버 상태 매핑 및 배경 휘도별 상태 표시 대비 3:1 이상을 검사합니다.
- `ConfirmationStateTest`: 확인 대상과 보호 백업 선택값 보존, 설치·브랜치 대상 보존, 알 수 없는 형식/작업/인자의 폐기, 안전하지 않은 파일명/URI 거부, 문서 URI의 데이터 복원을 검사합니다. 복원 함수에는 작업 실행 경로가 없습니다.

## 실제 검증 범위

- 코드의 Android API 분기와 Compose 구성요소는 독립 정적 검토를 받았습니다.
- 색상쌍의 최악 대비는 별도 수학 계산으로 3.11:1 이상임을 확인했습니다. 이 계산은 JUnit 또는 Android 렌더링 테스트 실행을 대신하지 않습니다.
- 작성 시점에 로컬 Kotlin 컴파일러/JUnit 실행 환경이 없어 위 JUnit 테스트는 실행하지 않았습니다. CI에서 테스트·컴파일·lint 결과를 확인해야 합니다.
- Android 실기기/에뮬레이터에서 스크린샷·Compose UI 테스트를 실행하지 않았습니다. 200% 글씨, 320dp 창, 720×360dp 가로 창, 태블릿/분할 화면에서 버튼 접근성·줄바꿈·탐색 스크롤을 별도로 확인해야 합니다.

## 확인창 회전 보존 구현

콜백 람다 대신 작업 enum과 파일명·URI·브랜치 같은 최소 인자, 보호 백업 선택값을 `ConfirmationCodec`/`rememberSaveable`로 저장합니다. 확인 버튼을 눌렀을 때만 현재 ViewModel의 메서드로 해석하며, 복원 자체는 작업을 실행하지 않습니다.

확인 시 저장 상태를 먼저 비운 뒤 실행하고, 모르는 작업이나 유효하지 않은 인자는 안전하게 폐기합니다. 저장 데이터 크기를 제한하며 외부 문서 URI의 읽기 권한이 사라지면 다시 선택하도록 안내합니다. 설치 작업은 저장해 둔 브랜치를 명시적으로 선택하므로 확인창의 대상과 실제 설치 대상이 달라지지 않습니다.

## 아직 실행하지 않은 Android UI 확인 절차

1. 복원/초기화 확인창에서 보호 백업을 해제한 뒤 화면을 회전합니다. 대상과 선택값이 유지되고, 확인 전에는 작업이 시작되지 않아야 합니다.
2. Staging 설치 확인창을 띄운 뒤 회전합니다. 확인하면 원래 선택한 Staging만 설치 대상으로 사용해야 합니다. URI 권한이 없는 복원 확인은 파일 재선택 안내로 끝나야 합니다.
3. 글씨 200%, 320dp 창과 720×360dp 가로 창에서 설치 정보·브랜치 버튼·위험 영역·탭·작업 창을 확인합니다. 이름/값이 겹치지 않고 모든 버튼과 메뉴에 스크롤로 접근할 수 있어야 합니다.
4. 작업 창을 펼친 상태에서 배경 버튼과 뒤로 가기를 눌러도 다른 작업이 실행되지 않아야 합니다. 접었다 펼치거나 회전해도 경과 시간이 처음부터 다시 시작하면 안 됩니다.
5. 시스템 테마에서 기기 밝기 모드가 바뀌는지, 모든 테마에서 선택한 강조색이 배경화면과 관계없이 유지되는지 확인합니다.
6. 서버가 꺼져 있으면 재시작 바로가기가 없고, 시작하면 다시 보여야 합니다. 작은 창에서는 하단 탐색, 넓은 창에서는 측면 탐색이 나타나며 선택된 화면은 그대로 유지돼야 합니다.
